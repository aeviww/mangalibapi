# ошибки

api возвращает ошибки в формате json. для большинства маршрутов тело имеет вид `{"data": {"toast": {...}}}`, для ошибок валидации - `{"data": {"<поле>": ["<сообщение>"]}}`.

## сводная таблица

| статус | возможное значение | что проверить |
|---|---|---|
| `400 Bad Request` | неверный формат запроса | путь, query-параметры, тело и `Content-Type` |
| `401 Unauthorized` | требуется авторизация | заголовок `Authorization: Bearer <token>` |
| `403 Forbidden` | доступ отклонён защитой или правилами | `Site-id`, `Referer`, HTTP/2, регион |
| `404 Not Found` | маршрут, `slug_url` или id не найдены | базовый хост, `Site-id`, идентификатор |
| `422 Unprocessable Entity` | ошибка валидации параметров | тело ответа с именами полей |
| `429 Too Many Requests` | превышен лимит запросов | `X-RateLimit-*`, частоту и параллельность |
| `5xx` | ошибка сервера или промежуточного сервиса | повторить позже с задержкой |

## `404 Not Found`

```json
{
  "data": {
    "toast": {
      "type": "silent",
      "message": "Not Found"
    }
  }
}
```

`type: "silent"` означает, что сайт не показывает это сообщение пользователю как отдельный popup. для клиента это всё равно ошибка.

## `401 Unauthorized`

```json
{
  "data": {
    "toast": {
      "type": "error",
      "message": "Вы не авторизованы"
    }
  }
}
```

проверьте, что токен передан именно как `Bearer <token>` и не истёк. 

## `422 Unprocessable Entity`

пример для `page=abc`:

```json
{
  "data": {
    "page": [
      "Поле page должно быть целым числом."
    ]
  }
}
```

пример для несуществующего `site_id[]`:

```json
{
  "data": {
    "site_id.0": [
      "The selected site_id.0 is invalid."
    ]
  }
}
```

пример для неизвестного `fields[]`:

```json
{
  "data": {
    "fields.0": [
      "Выбранное значение для fields.0 ошибочно."
    ]
  }
}
```

## `429 Too Many Requests`

```http
X-RateLimit-Limit: 100
X-RateLimit-Remaining: 0
```

при `429`:

1. прекратите повторные запросы;
2. подождите и увеличьте интервал;
3. уменьшите параллельность;
4. кешируйте свои запросы.

## возникли проблемы?

если вы столкнулись с ошибкой, обнаружили неточность в документации или хотите предложить улучшение, создайте [issue](https://github.com/aeviww/mangalibapi/issues) в репозитории проекта.

при описании проблемы укажите:
- какой маршрут использовался;
- параметры запроса;
- HTTP-статус и текст ошибки;
- ожидаемое и фактическое поведение.

перед публикацией убедитесь, что отсутствуют ваши конфиденциальные данные.
